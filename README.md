# oficina-git
primeiro entramos com nossa conta do GitHub para assim dar inicio a prática da oficina. o GIT E GITHUB VEM COMO UMA AJUDA PARA NÃO SALVAR VÁRIOS ARQUIVOS DE VERSÕES DE UM MESMO PROJETO, controlando a versão de um projeto.  Serve também para várias pessoas trabalharem em conjunto no mesmo projeto. Cada pessoa adiciona sua parte em um repositório remoto para juntar o arquivo num só. O Git é o repositório local e o GitHub é na nuvem para todos.
Git: Controle de histórico, trabalho em equipe, ramificação do projeto, segurança na organização.
GitHub: Hospedagem, repositórios ilimitados para hospedar o código fonte, serve como uma rede social, é possível publicar suas páginas web pelo pages, colaboração e forks (fazer alterações em outros projetos independente).

Repositório: Será onde tudo do projeto será armazenado.
Commit: Possibilita fazer uma alteração e subir para o repositórioi com uma sinalização para saber o que foi adicionado/alterado, mas ainda não subiu para o remoto, só localmente. Isso possibilita concertar erros que não foram enviados ainda.
Staging Area: é uma área onde você vai poder escolher os arquivos que serão enviados para o repositório.
Clone: Onde você pode pegar qualquer projeto e copiar para seu computador utilizando apenas o url.
Push: Pega o que tem nos seus commits e envia para o GitHub, para a nuvem de fato
Pull: Pega as alterações que estão na nuvem e coloca na máquina local.
git checkout: Possibilita ver em qual ramificação você está
branch: é uma modificação alternativa
merge: é juntar uma branch na outra, adicionando na principal
head: vai falar em qual commit a gente está

Ciclo de vida do código, possui três estágios.
Modificado: São os arquivos modificados na maquina local>
Staged: é quando os arquivos vão para a Staging Area para você escolher o que será commitado.
Commitado: è aquilo é que já está preparado para dar o push.
